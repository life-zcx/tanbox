# 🚀 Инструкция по развертыванию TANBOX в Production

Пошаговое руководство по первому запуску платформы TANBOX на чистом сервере Ubuntu (Serverspace / PS.kz) и последующим обновлениям.

---

## 📋 Требования к серверу
* **Провайдер:** Serverspace (Алматы) или PS.kz
* **Конфигурация:** 2 vCPU, 4 ГБ RAM, 50 ГБ SSD, сеть 30–50 Мбит/с
* **Операционная система:** Ubuntu 26.04 LTS / 24.04 LTS / 22.04 LTS (x86_64)

---

## ШАГ 1. Настройка DNS-записей домена (до запуска сервера)

В панели управления вашим доменом `tanbox.kz` (у регистратора, например PS.kz или Cloudflare) добавьте **A-записи**, указывающие на IP-адрес вашего сервера **`185.200.86.23`**:

| Тип | Имя поддомена (Хост) | Значение (IP) | Назначение |
| :--- | :--- | :--- | :--- |
| **A** | `@` (или оставить пустым) | `185.200.86.23` | Главный лендинг (`tanbox.kz`) |
| **A** | `www` | `185.200.86.23` | Зеркало лендинга (`www.tanbox.kz`) |
| **A** | `lk` | `185.200.86.23` | Личный кабинет клиента (`lk.tanbox.kz`) |
| **A** | `admin` | `185.200.86.23` | Панель администратора (`admin.tanbox.kz`) |
| **A** | `api` | `185.200.86.23` | REST API бэкенда (`api.tanbox.kz`) |

> ⏱️ *Примечание:* Обновление DNS обычно занимает от 5 до 30 минут. Это нужно для того, чтобы Caddy автоматически выписал бесплатные SSL-сертификаты Let's Encrypt (HTTPS).
> 
> 💡 *Быстрый тест до обновления DNS:* Вы можете открыть сайт на своем компьютере прямо сейчас, добавив в файл `C:\Windows\System32\drivers\etc\hosts` (или `/etc/hosts` на Mac/Linux) строчку:
> ```text
> 185.200.86.23 tanbox.kz www.tanbox.kz lk.tanbox.kz admin.tanbox.kz api.tanbox.kz
> ```

## ШАГ 2. Подключение к серверу по SSH

Откройте терминал (PowerShell или Git Bash на Windows) и подключитесь к серверу:

```bash
ssh root@185.200.86.23
```

## ШАГ 3. Загрузка проекта на сервер

### Вариант А: Если репозиторий в Git (Рекомендуется)
```bash
git clone <URL_ВАШЕГО_GIT_РЕПОЗИТОРИЯ> /opt/tanbox
cd /opt/tanbox
```

### Вариант Б: Копирование файлов напрямую с вашего ПК (PowerShell)
На вашем локальном компьютере в терминале выполните одну команду:
```powershell
scp -r "c:\Users\lgs03\Desktop\tanbox" root@185.200.86.23:/opt/tanbox
```
После завершения передачи, на сервере перейдите в каталог:
```bash
cd /opt/tanbox
```

## ШАГ 4. Автоматическая подготовка сервера (1 клик)

Запустите подготовленный скрипт настройки окружения:

```bash
sudo bash scripts/setup-server.sh
```

### Что скрипт сделает автоматически:
1. Создаст **4 ГБ SWAP** (`/swapfile`) с `swappiness = 10` для защиты от переполнения ОЗУ.
2. Установит официальный **Docker Engine** и **Docker Compose Plugin**.
3. Оптимизирует системные лимиты файлов ядра Linux.
4. Настроит фаервол **UFW** (откроет только безопасные порты: `22` SSH, `80` HTTP, `443` HTTPS).
5. Добавит в `cron` ночной автобэкап базы данных (каждую ночь в 03:00 со сжатием и хранением 14 дней).

---

## ШАГ 5. Настройка файла переменных окружения (.env)

Создайте рабочий файл `.env` из готового шаблона:

```bash
cp .env.example .env
nano .env
```

В файле `.env` укажите ваши боевые параметры:
* `POSTGRES_PASSWORD` — сложный пароль к базе данных (придумайте надежный).
* `JWT_SECRET` — сгенерируйте случайный ключ командой `openssl rand -hex 32`.
* `ENCRYPTION_SECRET` — сгенерируйте ключ шифрования для учетных записей ИС МПТ (минимум 32 символа, например `openssl rand -hex 16`).
* `INITIAL_ADMIN_PASSWORD` — стартовый пароль для входа супер-администратора `admin@tanbox.kz`.
* `TELEGRAM_BOT_TOKEN`, `TELEGRAM_LEADS_CHAT_ID`, `TELEGRAM_ALERTS_CHAT_ID` — токен вашего Telegram-бота для лидов и уведомлений.

*(Для сохранения файла в nano нажмите `Ctrl + O`, затем `Enter`, для выхода `Ctrl + X`)*.

---

## ШАГ 6. Запуск боевого продакшна

Запустите автоматический деплой:

```bash
bash scripts/deploy.sh
```

Скрипт выполнит:
1. Оптимизированную сборку всех Docker-контейнеров.
2. Синхронизацию схемы базы данных через Prisma.
3. Сидинг начальных тарифов и администратора `admin@tanbox.kz`.
4. Запуск всех 7 сервисов в фоне.
5. Очистку старых кэшированных слоев Docker для экономии места на диске.

---

## ШАГ 7. Проверка работоспособности

Проверьте статус запущенных контейнеров:

```bash
docker compose ps
```

Все контейнеры должны иметь статус `Up`:
* `tanbox_caddy` — Up (порты 80, 443)
* `tanbox_backend` — Up
* `tanbox_postgres` — Up (healthy)
* `tanbox_frontend_landing` — Up
* `tanbox_frontend_lk` — Up
* `tanbox_frontend_admin` — Up
* `tanbox_label_generator` — Up

Проверьте доступность через браузер:
* 🌐 Главный сайт: `https://tanbox.kz`
* 🌐 Личный кабинет: `https://lk.tanbox.kz`
* 🌐 Панель администратора: `https://admin.tanbox.kz`
* 🌐 Проверка API: `https://api.tanbox.kz/api/health`

## 🛠️ Полезные команды для обслуживания

### Просмотр логов в реальном времени:
```bash
# Логи бэкенда
docker compose logs -f backend

# Логи Caddy (выдача SSL и запросы)
docker compose logs -f caddy

# Логи всех сервисов
docker compose logs -f --tail 50
```

### Обновление проекта после правок в коде (Git pull):
```bash
cd /opt/tanbox
git pull
bash scripts/deploy.sh
```

### Ручное создание бэкапа базы данных прямо сейчас:
```bash
bash scripts/backup-db.sh
```
Архив сохранится в `/opt/tanbox/backups/tanbox_db_backup_ГГГГММДД_ЧЧММСС.sql.gz`.

### Безопасные миграции базы данных (Zero-Data-Loss):
Все изменения схемы БД происходят безопасно и аддитивно:
1. При каждом запуске `bash scripts/deploy.sh` автоматически создается резервная копия (`.sql.gz`) перед любыми действиями.
2. Применяются проверенные идемпотентные SQL-скрипты из `backend/prisma/migrations/` (`CREATE TABLE IF NOT EXISTS`, `DO $$ EXCEPTION WHEN duplicate_object`). Существующие таблицы и данные клиентов никогда не удаляются и не перезаписываются.
3. Если требуется применить миграцию вручную без перезапуска сервисов:
   ```bash
   docker exec -i tanbox_postgres psql -U tanbox_user -d tanbox_db < backend/prisma/migrations/20261014120000_add_invoices_table/migration.sql
   ```

### Перезапуск сервисов:
```bash
docker compose restart
```
